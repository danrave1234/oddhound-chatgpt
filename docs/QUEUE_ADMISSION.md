# Bounded run admission and queue recovery

Verified-site requests can now wait for the single browser slot. Previously, every active run caused admission to reject another principal; the worker also lacked a durable deferral path if another worker held capacity. `packages/db/admission.ts` now owns transactional public admission, queue deadlines, cancellation and canonical UI/API-origin locks. The web entry point retains authentication, ownership/configuration and public-release gates before calling it.

Admission locks the public ledger, expires due queued entries, rolls the UTC day bucket, checks the $7/$50 spent-plus-held ceilings, three-run user quota, one pending request per principal and 20 pending requests globally. It freezes the same owner contract and locks every active primary/API origin across projects/users in stable order. Resource-only origins acquire no action lock. Exploration reserves $2; deterministic fixed-assertion work reserves no model money. All insertions, origin locks, reservations and the outbox commit together. An exception rolls the entire admission back.

`claimQueuedRun` enforces the single executing slot in PostgreSQL, including retained compute reservations and unterminated Machines, and takes the oldest eligible queued request first. Competing processes cannot each claim a browser slot. Busy jobs use BullMQ's locked `moveToDelayed` plus `DelayedError`, keeping the same job ID and its single execution attempt. They do not silently complete or repeat active execution. The exact pinned PostgreSQL backend passes this behavior; the [official pattern](https://github.com/taskforcesh/bullmq/blob/master/docs/gitbook/patterns/process-step-jobs.md) and [PostgreSQL guide](https://github.com/taskforcesh/bullmq/blob/master/docs/gitbook/guide/postgresql.md) were checked alongside the installed 6.4.2 types.

Queued work expires after 15 minutes; the separate 15-minute execution deadline starts at provisioning. The independent reaper expires queued entries before any Fly cleanup call. Admission and claim also check expiry. Expired/cancelled queued work returns its unused reservation/quota once. Active cancellation fences the generation and retains origin locks through stopping/finalizing. A database guard refuses terminal status while a browser allocation, unterminated Machine or compute hold remains; confirmed cleanup marks the allocation released, then terminal status releases the origin locks atomically. The public ledger also rejects negative balances.

The owner-bound workspace/detail API exposes only numeric queue position and its deadline, never another principal's target, identity or goal. The UI distinguishes queued work from a captured browser stream and labels an unused model as planned. [Before cancellation](assets/queue-ui.png) and [after cancellation](assets/queue-ui-stopped.png) show an explicitly **synthetic** presentation fixture. [HTTP/UI evidence](evidence/queue-ui.json) confirms its real cancellation with zero actions, turns or spend. That fixture was never scheduled for execution.
