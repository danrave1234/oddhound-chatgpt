# Product requirements

Oddhound is an active exploratory testing product. A GitHub-signed-in owner verifies an exact public HTTPS origin, approves an immutable capability/account/test-data contract and lets a Meta-driven agent discover and exercise the interface. It must work beyond a curated demo. The owner may authorize production writes with suitable test accounts and explicit effects; observation-only is optional.

- Ownership uses a per-user/origin/revision 256-bit token in DNS TXT, a well-known text file, or a real head meta tag. Recheck before every run/resume. Helpers reject redirects, private/internal/metadata/6PN destinations, pin validated addresses at dial, preserve TLS checks and bound responses.
- Primary UI and independently verified first-party API authority are separate. Public resources carry no action authority. A newly discovered endpoint never expands origins, actors, fixture ownership or forbidden effects.
- Run-level grants permit signup/login and synthetic create/edit/cancel, boundaries, repeats and unusual order. Generic browser code cannot infer every business side effect. Use synthetic staging data and least-privilege test accounts, with narrower grants where necessary. No per-click approval or prescribed discovery script.
- One fresh pinned Fly Machine per run in a separate browser app. No platform credentials, persistent volumes, profile reuse or public control service. Non-root Chromium sandbox enabled; private source-restricted control; smokescreen and firewall enforce actual destinations. The rejected CDP worker workaround is not production containment. The gateway candidate needs complete resource/deployed proof before exposure. Never silently disable sandbox, TLS validation or network controls.
- Durable PostgreSQL queue/outbox, action intents and generation fences prevent blind replay of uncertain writes. Stop/expiry closes action authority; destroy and confirm the Machine, with an independent orphan reaper. Unknown creation/deletion retains capacity. Compute is budgeted separately from model spend.
- Three runs per user per UTC day, one run per site and one initial global browser slot, at most one action per second, 250 actions, 60 model turns and 15 minutes. Reserve model spend before every attempt. Preserve unknown reservations. Public ceilings: $2/run, $7/day and $50 lifetime; $15 judging reserve requires authenticated special authorization. Anonymous demo use never receives judge funds.
- Primary model: Direct Meta `muse-spark-1.3`, Standard mode, `https://api.meta.ai/v1`. Tool choice auto, explicit temperature, validated tool arguments, exact assistant tool-call replay, finish_run tool. Images belong in a user message following a tool response. Never send platform keys or target credentials to the model; resolve credential references in trusted code.
- No arbitrary model eval, shell or generated runner code. Use fixed trusted tools and test templates. A finding is verified only after saved independent evidence contradicts an explicit rule; candidates remain separate. Assertions and versions stay unchanged on retest. Fix briefs separate observations and hypotheses and never invent source paths.
- Ship a sign-in-free owned synthetic demo target and a clearly labelled recorded replay. Claims, activity and screenshots must come from real execution; no invented thinking, live badges or success metrics. All applicable platform/tenant/budget/fixture gates apply before live public demos or verified-site exposure.
- Stack: pinned Node 26, Next >=16.4.3, React >=19.3.1, Playwright 1.64.1, Drizzle 0.45, Better Auth/GitHub user:email, BullMQ 6 PostgreSQL backend, pnpm. No Redis, legacy MCP SDK, second browser/agent framework, Lucide, Kubernetes, vector or graph database.
- Preserve the macOS-inspired three-pane UI and original hound branding. Use the central Octicons/original SVG layer. Support keyboard focus, reduced motion and responsive inspection.

Build complete proof milestones, without the obsolete fixed nine-day deadline. Implementation tests establish behavior of the product being built; they do not constitute a standalone blocker audit or waive release requirements.
